## 1. アプリ概要

本アプリケーションは、アパレル販売店における在庫確認を支援するWebアプリケーションである。商品情報、店舗情報、店舗ごとの在庫情報を管理し、現在庫・基準在庫数・週間販売数をもとに、「欠品危険」「要補充」「適正在庫」「過剰気味」などの在庫状態を表示する。これにより、担当者が在庫状況をひと目で確認し、補充が必要な商品を見つけやすくすることを目的とする。

今回は在庫状態の可視化と補充確認の目安表示を中心に実装するが、将来的には売上実績、季節要因、入荷予定などを加味した補充提案機能への拡張も想定している。

---

## 2. 制作背景・解決したい課題

アパレル販売店では、商品ごとにサイズやカラーの展開があり、管理する在庫数が多くなりやすい。そのため、在庫状況を確認するだけでも時間がかかり、経験の浅い担当者にとっては、どの商品から確認・補充すべきか判断しにくい場合がある。

自身も前職でアパレル販売に従事し、在庫管理業務を行う中で、商品情報や数値情報が一覧に並ぶだけでは、現在の状態や確認すべき商品が分かりにくいと感じる場面があった。

そこで本アプリでは、現在庫・基準在庫数・週間販売数をもとに在庫状態を分かりやすく表示し、補充確認の目安を示すことで、担当者が在庫状況を把握しやすくする。これにより、在庫管理業務の効率化と、担当者ごとの判断のばらつきの軽減を目指す。

---

## 3. 想定ユーザー

本アプリケーションの想定ユーザーは、アパレル販売店において在庫管理や補充判断を担当する従業員である。

主な対象は、在庫管理を新たに担当することになった一般社員やパートスタッフである。衣料品は商品数に加えてサイズやカラー展開も多く、経験が浅い担当者にとっては、どの商品を優先して確認・補充すべきか判断しにくい場合がある。そのため、本アプリでは商品の状態や補充の優先度を分かりやすく表示し、経験の浅い担当者でも在庫状況を把握しやすくすることを目指す。

また、店長や在庫管理責任者にとっても、補充が必要な商品を短時間で確認できることで、日々の確認作業や指示出しの効率化につながるツールとして利用できることを想定している。

本アプリは量販店・小売店への応用も可能であるが、今回は自身の実務経験をもとに、アパレル販売店における在庫管理業務の課題改善を主な対象として設計する。

## 7. 在庫判定ロジック

本システムでは、現在庫・必要在庫・週間販売実績をもとに、在庫状態をA〜Dの判定ランクで表示する。

**計算式**

- 差分 ＝ 現在庫 − 必要在庫
- 在庫週数 ＝ 現在庫 ÷ 週間販売実績
- 次回入庫候補数 ＝ 必要在庫 − 現在庫

**判定ランク**

| ランク | 状態 | 条件 |
|--------|------|------|
| A | 適正在庫 | D、C、Bのいずれにも該当しない場合。 |
| B | 在庫過多 | 現在庫が必要在庫を上回り、かつ在庫週数が4週以上の場合。 |
| C | 在庫過少 | 現在庫が必要在庫を下回る場合、または在庫週数が1週未満の場合。 |
| D | 欠品 | 現在庫が0の場合。 |

## 8. DB設計 - テーブル一覧

| テーブル名 | 役割 | 主な関連テーブル | 備考 |
|------------|------|-----------------|------|
| **products** | 商品の基本情報を管理する | product_variants | 商品名やカテゴリを管理 |
| **product_variants** | 商品ごとのサイズ・カラー情報を管理する | products, inventories | SKU単位の管理を行う |
| **stores** | 店舗情報を管理する | inventories | 店舗名などを保持 |
| **inventories** | 店舗ごとの在庫情報を管理する | stores, product_variants | 現在庫数や基準在庫数を保持 |
| **store_products** | 店舗ごとの取扱商品を管理する | stores, products | 店舗と商品の多対多関係を管理する中間テーブル |

> ※ 判定ランクや補充推奨数はDBに保存せず、在庫情報からシステム側で算出する。

**テーブル名：** `store_products`　**役割：** 店舗ごとの取り扱い商品を管理する  
**備考：** 店舗と商品の多対多関係を管理する中間テーブル

| カラム名 | 型 | NULL | キー | 初期値 | 備考 |
|----------|----|------|------|--------|------|
| id | BIGINT UNSIGNED | 不可 | PK | AUTO_INCREMENT | 取り扱い商品ID |
| store_id | BIGINT UNSIGNED | 不可 | FK | なし | stores.idと紐づく |
| product_id | BIGINT UNSIGNED | 不可 | FK | なし | products.idと紐づく |
| is_active | TINYINT(4) | 不可 |  | 1 | 1：取扱中、0：取扱停止 |
| created_at | TIMESTAMP | 可 |  | NULL | 登録日時 |
| updated_at | TIMESTAMP | 可 |  | NULL | 更新日時 |

### 制約

- `store_id` と `product_id` の組み合わせに UNIQUE 制約を設定する。
- これにより、同じ店舗と同じ商品が重複して登録されないようにする。
